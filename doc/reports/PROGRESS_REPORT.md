> **overall_score** = 5개 점수의 단순 평균 (각 20% 가중치)

#### 성능 개선 분석 (2026-01-24)

⚠️ **audible_range_score 주의사항**:

| 값 | 개수 | 비율 |
| ---- | ---- | ---- |
| 5.0 | 2,374개 | 96% |
| 4.0 | 110개 | 4% |

현대차가 거의 모든 차량에 5.0점을 부여하여 **분산이 거의 없는 점수**입니다.
모델이 5.0을 예측하면 자동으로 MAE가 낮아지므로, 이 점수의 개선은 인위적입니다.

**실제 vs 인위적 개선 분해**:

| 구분 | 개선율 | 설명 |
| ---- | ---- | ---- |
| audible_range_score | -83% | ⚠️ 데이터가 상수라서 |
| 나머지 4개 점수 평균 | **~13%** | ✅ 실제 학습 개선 |
| 전체 평균 (MAE) | 24.4% | 혼합 효과 |

> **결론**: 24.4% 개선 중 **실질적 개선은 ~13%**, 나머지는 audible_range_score 분포 특성

## 3. 기술 아키텍처

### 3.1 전처리 파이프라인
```
MP3 오디오 → STFT(2048) → HPSS 분리 → 스펙트로그램(128x128) → 정규화
```

**핵심 파라미터**:
- Sample Rate: 22,050 Hz
- FFT Size: 2,048
- Hop Length: 512
- Max Frequency: 6,000 Hz (엔진 핵심 주파수 대역)

### 3.2 모델 구조
```
Input(128x128x1) → Conv2D(4층) → CBAM Attention → GlobalAvgPool → Dense(5)
```

**CBAM (Convolutional Block Attention Module)**:
- 채널 어텐션: 주파수 대역별 중요도 학습
- 공간 어텐션: 시간-주파수 위치별 중요도 학습
- 효과: +14.5% 성능 향상

### 3.3 MLOps 구조 (신규 구현)
```
egai/
├── data/           # 데이터 수집 및 관리
│   └── crawler/    # 웹 크롤러
├── preprocessing/  # 오디오 전처리
├── pipelines/      # 실험 추적 및 학습
└── infrastructure/ # 모델 정의
```

## 4. 주요 발견 사항

### 4.1 성공 요인

| 요인 | 효과 | 설명 |
|------|------|------|
| CBAM Attention | +14.5% | 중요 주파수 대역 자동 학습 |
| STFT (Mel 대신) | +69% | 엔진음 특성에 적합 |
| GlobalAvgPool | 파라미터 99.8% 절감 | 과적합 방지 |
| 5-Fold Stratified CV | 안정성 확보 | 편향 없는 평가 |

### 4.2 실패 요인 (시도했으나 효과 없음)

| 시도 | 결과 | 원인 분석 |
|------|------|----------|
| 물리량 특징 추가 | -40% 악화 | 데이터 부족으로 과적합 |
| 메타데이터 결합 | -51% 악화 | 과적합 |
| 모듈레이션 특징 | -27% 악화 | 과적합 |
| Mel Spectrogram | -69% 악화 | 음성용 (엔진음 부적합) |
| 데이터 증강 2x | 효과 없음 | 노이즈만 추가 |

### 4.3 핵심 인사이트

> **"단순함이 최고"**: 594개 데이터에서는 복잡한 모델보다 단순한 모델이 더 효과적
