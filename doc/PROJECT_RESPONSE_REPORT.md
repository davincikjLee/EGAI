## 1.2 크롤러 CSV 문제 해결

### 문제 1: 글꼴 깨짐 현상

**원인:**
CSV 파일을 엑셀에서 열 때 한글 인코딩(UTF-8)을 인식하지 못함

**해결 방법:**
1. 엑셀에서 "데이터 → 텍스트에서" 메뉴 사용
2. 인코딩을 "UTF-8"로 선택
3. 또는 메모장에서 열어 "다른 이름으로 저장" → ANSI로 저장

**코드 수정 (영구 해결):**
```python
# data_manager.py에서
df.to_csv(path, index=False, encoding='utf-8-sig')  # BOM 추가
```
`utf-8-sig`를 사용하면 엑셀에서 바로 열어도 한글이 정상 표시됩니다.

### 문제 2: 데이터 열 밀림

**원인:**
데이터 값 안에 쉼표(,)가 포함되어 CSV 구분자와 충돌

**해결 방법:**
```python
# 값에 쉼표가 있으면 따옴표로 감싸기
df.to_csv(path, index=False, quoting=csv.QUOTE_ALL)
```

## 1.3 데이터 부족 문제 (문의점 2)

### 현재 데이터 현황

| 항목 | 수량 | 비고 |
|------|------|------|
| 전체 수집 데이터 | 2,236건 | |
| 라벨링된 데이터 (가솔린) | 555건 | 학습에 사용 |
| 점수별 분포 | 불균형 | 4~5점이 대부분 |

### 점수별 데이터 분포 (실제)

```
irregularity (불규칙성) 분포:
  2점:    9개 ( 1.6%)  ← 매우 적음
  3점:   80개 (14.6%)
  4점:  118개 (21.5%)
  5점:  341개 (62.2%)  ← 대부분

audible_range_score (가청범위) 분포:
  4점:   30개 ( 5.5%)
  5점:  518개 (94.5%)  ← 거의 전부
```

### 왜 이렇게 불균형한가?

**핵심 이유: 현대 인증 중고차는 "좋은 차"만 있음**

- 인증 중고차는 현대차가 품질 검수를 통과한 차량만 판매
- 고장난 차, 상태 안 좋은 차는 인증을 받지 못함
- 따라서 대부분 4~5점 (양호~우수) 데이터만 존재

**과적합 우려 → 실제로 발생함:**
- 모델이 "대부분 5점"이라고 학습
- 새로운 데이터도 무조건 5점 근처로 예측
- 실제 2점짜리가 와도 5~6점으로 예측하는 문제 확인됨

## 1.4 스펙트로그램 시각화 문제 (문의점 3)

### "다 비슷하게 초록색으로 보인다"는 문제

**이유:**
1. 정상 엔진은 원래 소리 패턴이 비슷함
2. 육안으로는 차이가 미미해 보임
3. 하지만 AI는 숫자로 계산하므로 미세한 차이도 구분 가능

### 실제 AI가 보는 차이 (예시)

```
사람 눈: "둘 다 초록색이네"
AI 계산:
  - A 엔진: [0.234, 0.567, 0.891, ...]
  - B 엔진: [0.245, 0.558, 0.903, ...]
  → 미세하지만 패턴 차이 존재
```

### 피드백 시각화 (구현 완료)

**현재 제공되는 리포트:**
```
experiments/
└── 20260114_025701_64b475/
    ├── results.json      # 성능 수치
    ├── config.json       # 실험 설정
    └── data_splits.json  # 데이터 분할 정보
```

**결과 예시:**
```
[결과 요약]
전체 MAE: 0.4578 ± 0.0179
최고 Fold: 3 (MAE: 0.4323)

[컬럼별 MAE]
  low_high_freq: 0.4814
  mid_freq_score: 0.5043
  audible_range_score: 0.1040  ← 가장 정확
  regularity: 0.5475
  irregularity: 0.6520         ← 가장 어려움
```

## 2.2 논문과 비교

### 참고 논문
"소음 데이터를 이용한 딥러닝 기반의 차량 진단 기술 개발"
(현대자동차 + KAIST, 2023)

### 논문과 같은 점

| 항목 | 내용 |
|------|------|
| 입력 데이터 | 엔진 소리 → 스펙트로그램 변환 |
| 기본 모델 | CNN (Convolutional Neural Network) |
| 출력 | 5개 품질 점수 예측 |
| 평가 방법 | MAE (Mean Absolute Error) |

### 논문과 다른 점 (우리가 개선한 부분)

| 항목 | 논문 | 현재 | 효과 |
|------|------|------|------|
| 어텐션 | 없음 | **CBAM 적용** | +14.5% 성능 향상 |
| 입력 채널 | 1개 | **4개** | 다양한 특징 추출 |
| 모델 구조 | Single-head | **Multi-head** | 작업별 전문화 |
| 실험 관리 | 수동 | **자동화 (MLOps)** | 재현성 확보 |

### CBAM (어텐션)이란? - 쉽게 설명

**비유: 사진에서 중요한 부분 찾기**

```
일반 CNN:     사진 전체를 똑같이 봄
CBAM 적용:    "이 부분이 중요해!" 하고 집중

엔진 소리에서:
- 특정 주파수 대역에 집중 (채널 어텐션)
- 특정 시간대에 집중 (공간 어텐션)
```

| 모델 | MAE (낮을수록 좋음) | 개선율 |

### MAE 0.4578의 의미

```
5점 만점 기준으로:
- 평균 0.46점 정도의 오차
- 실제 4점인 차량 → 3.5~4.5점으로 예측
- 대략 "1등급 이내"의 정확도
```

| irregularity | 0.65 | 16.3% | 정확 |

| regularity | 0.55 | 18.2% | 정확 |

## 2.4 한계점과 해결 방안

### 한계점 1: 낮은 점수 예측 불가

**현상:**
```
실제 2점인 엔진 → AI가 5~6점으로 예측
```

**원인:**
- 학습 데이터에 2점짜리가 9개밖에 없음
- AI가 "2점이 어떤 소리인지" 충분히 학습하지 못함

**해결 가능성:**
| 방법 | 난이도 | 효과 |
|------|--------|------|
| 더 많은 데이터 수집 | 높음 (정비소 협력 필요) | 근본 해결 |
| 데이터 증강 (Augmentation) | 중간 | 부분 개선 |
| 서비스 설계로 우회 | 낮음 | 현실적 |

### 한계점 2: 이상 엔진 데이터 없음

**현상:**
- "고장난 엔진 소리"가 데이터에 없음
- 고장 탐지가 사실상 불가능

**해결 방안:**
→ 서비스 모델 제안에서 상세 설명

### 한계점 3: 출력 범위 제한 없음

**현상:**
```
5점 만점인데 6점으로 예측하는 경우 발생
```

**해결책 (즉시 적용 가능):**
```python
# 모델 출력을 1~5점 범위로 제한
예측값 = max(1, min(5, 예측값))
```

# 3. 서비스 모델 제안

## 3.1 핵심 발상의 전환

### 기존 접근 (문제 있음)

```
"엔진 품질 점수를 1~5점으로 예측한다"
→ 1~2점 예측이 안 됨 (데이터 부족)
→ 서비스 신뢰도 하락
```

### 새로운 접근 (제안)

```
"현대 인증 중고차 수준인지 확인한다"
→ 4~5점 범위만 판단 (데이터 충분)
→ 자신 있는 영역에서만 서비스
```

**비유:**
- 기존: "이 차는 몇 점입니다" (전 구간 예측)
- 제안: "이 차는 인증 중고차 수준입니다" (합격/불합격)

---

## 3.2 2단계 서비스 구조

```
┌─────────────────────────────────────────────┐
│           사용자 엔진 소리 녹음              │
└─────────────────┬───────────────────────────┘
                  ↓
┌─────────────────────────────────────────────┐
│  [1단계] 이상 탐지 (무료)                    │
│                                             │
│  "정상 범위의 소리인가?"                     │
│  → 4~5점 데이터로 학습한 오토인코더 사용     │
│                                             │
│  결과:                                       │
│  ✓ "안심 범위" → 2단계로                    │
│  ⚠ "점검 권장" → 정비소 연결 (무료 종료)    │
└─────────────────┬───────────────────────────┘
                  ↓ (안심 범위인 경우만)
┌─────────────────────────────────────────────┐
│  [2단계] 상세 스코어 (유료)                  │
│                                             │
│  "현대 인증 중고차 기준 어느 수준인가?"       │
│  → Multi-head CBAM 모델 사용                │
│                                             │
│  결과:                                       │
│  "상위 20% 수준입니다"                       │
│  "평균 수준입니다"                           │
│  "하위 30% 수준입니다"                       │
└─────────────────────────────────────────────┘
```

---

## 3.3 왜 이렇게 설계했나?

### 이유 1: 기술적 한계를 인정

| 우리가 잘하는 것 | 우리가 못하는 것 |
|-----------------|-----------------|
| 4~5점 범위 구분 | 1~2점 예측 |
| "정상 같다" 판단 | "어떤 고장이다" 진단 |

→ **잘하는 것만 유료화, 못하는 것은 "점검 권장"으로**

### 이유 2: 법적 리스크 최소화

| 시나리오 | 리스크 | 우리 대응 |
|---------|--------|----------|
| "정상"이라 했는데 실제 고장 | 매우 높음 | "안심 범위"로 표현 + 면책 |
| "이상"이라 했는데 실제 정상 | 중간 | 무료 제공 + 재측정 유도 |
| "점검 권장" → 고객 불만족 | 낮음 | 정비소 연결로 가치 제공 |

### 이유 3: 수익 모델 명확화

```
무료: 1차 스크리닝 (정상/점검권장)
     → 사용자 획득, 신뢰 구축

유료: 2차 상세 리포트 (9,900원)
     → "안심 범위" 판정받은 사용자만 대상
     → 신뢰도 높은 결과만 제공
```

### 기술적 한계를 비즈니스로 해결

| 문제 | 기술적 한계 | 비즈니스 솔루션 |
|------|------------|----------------|
| 저점수 예측 불가 | 데이터 부족 | "점검 권장"으로 전환 |

### 서비스 핵심 가치

> **"당신의 엔진이 현대 인증 중고차 수준인지 확인해드립니다"**

- ✕ 절대적 점수 → ✓ 상대적 위치
- ✕ 이상 진단 → ✓ 안심 인증
- ✕ 기술 과시 → ✓ 사용자 가치

## 부록: 자주 묻는 질문

### Q1: 왜 고장 진단을 안 하나요?

**A:** 고장난 엔진 데이터가 없어서 학습이 불가능합니다.
인증 중고차는 모두 검수를 통과한 "좋은 차"만 있습니다.
향후 정비소 협력을 통해 고장 데이터를 확보하면 가능합니다.

### Q2: 정확도를 더 높일 수 없나요?

**A:** 현재 MAE 0.46 (5점 만점 기준 약 0.5점 오차)입니다.
더 높이려면:
1. 더 많은 데이터 필요 (현재 555개 → 2,000개 이상)
2. 다양한 상태의 차량 데이터 필요
3. 정비 이력과 연동된 라벨링 필요

### Q3: 실제 서비스까지 얼마나 걸리나요?

**A:**
- MVP (무료 스크리닝만): 3개월
- 유료 서비스 포함: 6개월
- B2B 확장: 12개월

### Q4: 스마트폰 녹음 품질로 충분한가요?

**A:** 현재 MP3 데이터로 학습했으므로 스마트폰 녹음으로 충분합니다.
단, 녹음 환경(주변 소음, 거리 등)에 따라 결과가 달라질 수 있습니다.
앱에서 녹음 가이드를 제공할 예정입니다.
