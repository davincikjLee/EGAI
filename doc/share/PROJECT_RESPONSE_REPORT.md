## 1.2 크롤러 CSV 문제 해결

### 문제 1: 글꼴 깨짐 현상

**원인:**
CSV 파일을 엑셀에서 열 때 한글 인코딩(UTF-8)을 인식하지 못함

**해결 방법:**
1. 엑셀에서 "데이터 → 텍스트에서" 메뉴 사용
2. 인코딩을 "UTF-8"로 선택
3. 또는 메모장에서 열어 "다른 이름으로 저장" → ANSI로 저장

**코드 수정 (영구 해결):**
```python
# data_manager.py에서
df.to_csv(path, index=False, encoding='utf-8-sig')  # BOM 추가
```
`utf-8-sig`를 사용하면 엑셀에서 바로 열어도 한글이 정상 표시됩니다.

### 문제 2: 데이터 열 밀림

**원인:**
데이터 값 안에 쉼표(,)가 포함되어 CSV 구분자와 충돌

**해결 방법:**
```python
# 값에 쉼표가 있으면 따옴표로 감싸기
df.to_csv(path, index=False, quoting=csv.QUOTE_ALL)
```

## 1.3 데이터 부족 문제 (문의점 2)

### 현재 데이터 현황

| 항목 | 수량 | 비고 |
|------|------|------|
| 전체 수집 데이터 | 2,236건 | |
| 라벨링된 데이터 | 2,234건 | 학습에 사용 |
| 점수별 분포 | 불균형 | 4~5점이 대부분 |

### 점수별 데이터 분포 (실제)

```
irregularity (불규칙성) 분포:
  2점:    9개 ( 1.6%)  ← 매우 적음
  3점:   80개 (14.6%)
  4점:  118개 (21.5%)
  5점:  341개 (62.2%)  ← 대부분

audible_range_score (가청범위) 분포:
  4점:   30개 ( 5.5%)
  5점:  518개 (94.5%)  ← 거의 전부
```

### 왜 이렇게 불균형한가?

**핵심 이유: 현대 인증 중고차는 "좋은 차"만 있음**

- 인증 중고차는 현대차가 품질 검수를 통과한 차량만 판매
- 고장난 차, 상태 안 좋은 차는 인증을 받지 못함
- 따라서 대부분 4~5점 (양호~우수) 데이터만 존재

**과적합 우려 → 실제로 발생함:**
- 모델이 "대부분 5점"이라고 학습
- 새로운 데이터도 무조건 5점 근처로 예측
- 실제 2점짜리가 와도 5~6점으로 예측하는 문제 확인됨

## 1.4 스펙트로그램 시각화 문제 (문의점 3)

### "다 비슷하게 초록색으로 보인다"는 문제

**이유:**
1. 정상 엔진은 원래 소리 패턴이 비슷함
2. 육안으로는 차이가 미미해 보임
3. 하지만 AI는 숫자로 계산하므로 미세한 차이도 구분 가능

### 실제 AI가 보는 차이 (예시)

```
사람 눈: "둘 다 초록색이네"
AI 계산:
  - A 엔진: [0.234, 0.567, 0.891, ...]
  - B 엔진: [0.245, 0.558, 0.903, ...]
  → 미세하지만 패턴 차이 존재
```

### 피드백 시각화 (구현 완료)

**현재 제공되는 리포트:**
```
experiments/
└── 20260114_025701_64b475/
    ├── results.json      # 성능 수치
    ├── config.json       # 실험 설정
    └── data_splits.json  # 데이터 분할 정보
```

**결과 예시:**
```
[결과 요약]
전체 MAE: 0.4578 ± 0.0179
최고 Fold: 3 (MAE: 0.4323)

[컬럼별 MAE]
  low_high_freq: 0.4814
  mid_freq_score: 0.5043
  audible_range_score: 0.1040  ← 가장 정확
  regularity: 0.5475
  irregularity: 0.6520         ← 가장 어려움
```

## 1.5 더 좋은 분석 방법 (문의점 4)

### 논문 기반 구조 vs 현재 개선된 구조

| 항목 | 논문 구조 | 현재 구조 | 개선점 |
|------|----------|----------|--------|
| 입력 | 1채널 스펙트로그램 | **4채널** 스펙트로그램 | +3채널 추가 |
| 모델 | 기본 CNN | **CNN + CBAM 어텐션** | 중요 특징 강조 |
| 출력 | 단일 헤드 | **Multi-head (2개)** | 작업별 전문화 |

**4채널 입력이란?**
```
채널 1: Full Spectrogram     - 전체 소리
채널 2: Percussive           - 충격음 (노킹 소리 등)
채널 3: Difference           - 시간에 따른 변화량
채널 4: Variance Map         - 불안정한 영역 강조
```

## 2.2 논문과 상세 비교

### 참고 논문
**"소음 데이터를 이용한 딥러닝 기반의 차량 진단 기술 개발"**
- 저자: 노경진†, 이동철, 진재민, 정인수 (현대자동차), 장준혁 (한양대)
- 학회: 한국소음진동공학회논문집, Vol.33 No.3, 2023
- DOI: 10.5050/KSNVE.2023.33.3.306

---

### 논문 시스템 구조 (Fig. 1)

```
┌─────────────┐
│   Dataset   │
└──────┬──────┘
       ↓
┌─────────────────┐
│  Pre-Processing │  ← 피크 정규화 + STFT + HPSS
└──────┬──────────┘
       ↓
┌─────────────────────────────────────────────────┐
│            Fault Diagnosis Model               │
│         (분류 모델 - 고장 진단)                 │
│                                                │
│  결과: 정상 / 오토텐셔너 / 캠샤프트 / ...       │
└──────┬──────────────────────────────────────────┘
       ↓ (정상인 경우만)
┌─────────────────────────────────────────────────┐
│           NLI Regression Model                 │
│      (회귀 모델 - 소음 레벨 지수 추정)          │
│                                                │
│  결과: NLI 0~5 실수값 → 반올림하여 1~5 정수    │
└─────────────────────────────────────────────────┘
```

---

### 핵심 비교: 논문 vs EGAI 현재 구현

#### 1. 시스템 목적

| 구분 | 논문 | EGAI 현재 |
|------|------|-----------|
| **1차 목표** | 고장 진단 (Classification) | 품질 점수 예측 (Regression) |
| **2차 목표** | 소음 레벨 지수 추정 | - |
| **대상 데이터** | 디젤 엔진 80대 (통제된 환경) | 가솔린 엔진 2,234대 (인터넷 수집) |
| **타겟 부품** | 오토텐셔너, 캠샤프트, 댐퍼풀리, 타이밍체인 | 일반 품질 점수 |

**차이점 설명:**
- 논문은 "고장 vs 정상" **이진 분류**가 주목적
- EGAI는 "품질 점수 1~5점" **연속 회귀**가 주목적
- 논문은 고장 부품을 인위적으로 조립하여 고장 데이터 확보
- EGAI는 인증 중고차만 있어 고장 데이터 없음

---

#### 2. 전처리 방법

| 구분 | 논문 | EGAI 현재 |
|------|------|-----------|
| **정규화** | Peak 정규화 (max=1) | Peak 정규화 (동일) |
| **변환** | STFT → Log Scale Spectrogram | STFT → Log Scale Spectrogram (동일) |
| **HPSS** | Percussive 성분 추출 | Percussive 성분 추출 (동일) |
| **샘플링** | 16 kHz | 16 kHz (동일) |
| **프레임** | 150ms / 75ms hop | 2048 / 512 hop (≈128ms / 32ms) |
| **FFT** | 4096 | 2048 |
| **녹음 시간** | 5초 | 4초 |

**차이점 설명:**
- 논문은 아이들 RPM 고려한 프레임 설정 (150ms)
- EGAI는 더 짧은 프레임 (128ms)으로 시간 해상도 높임
- 논문은 FFT 4096 (주파수 해상도 높음)
- EGAI는 FFT 2048 (계산 효율성)

---

#### 3. 모델 구조 상세 비교

**논문의 분류 모델 (Fig. 3):**
```
[Log Spectrogram]    [Log Spectrogram (Perc)]
       ↓                       ↓
 Conv Block              Conv Block
       ↓                       ↓
    CBAM                    CBAM
       ↓                       ↓
 Max-Pooling            Max-Pooling
       ↓                       ↓
 Conv Block              Conv Block
       ↓                       ↓
    CBAM                    CBAM
       ↓                       ↓
 Max-Pooling            Max-Pooling
       └─────────┬─────────┘
                 ↓ (Reshape & Concat)
          Fully Connected
                 ↓
          Fully Connected
                 ↓
            Softmax → 6개 클래스 확률
```

**논문의 회귀 모델 (Fig. 6):**
```
[Log Spectrogram + Percussive]  ← 채널 결합 입력
              ↓
       Conv Block
              ↓
           CBAM
              ↓
       Max-Pooling
              ↓
         (× 4회 반복)
              ↓
          Reshape
              ↓
    Fully Connected
              ↓
     Sigmoid × 5  → 0~5 실수값
```

**EGAI Multi-head CBAM 모델:**
```
[4채널: Full + Perc + Diff + Var]
              ↓
       Conv Block (64)
              ↓
           CBAM
              ↓
       Max-Pooling
              ↓
       Conv Block (128)
              ↓
           CBAM
              ↓
       Max-Pooling
              ↓
       Conv Block (256)
              ↓
           CBAM
              ↓
    Global Average Pooling
              ↓
         Dense (256)
              ↓
     ┌───────┴───────┐
     ↓               ↓
[Freq Head]    [Reg Head]
  Dense(128)     Dense(128)
     ↓               ↓
  Dense(3)       Dense(2)
     ↓               ↓
  3개 점수       2개 점수
(저고주파,중주파,  (규칙성,
 가청범위)       불규칙성)
```

| 구분 | 논문 | EGAI |
|------|------|------|
| **입력 채널** | 2개 (Full, Perc) | **4개** (Full, Perc, Diff, Var) |
| **입력 방식** | 분류: 분리 → 결합 / 회귀: 채널 결합 | 채널 결합 |
| **Conv 블록 수** | 2개 (분류) / 4개 (회귀) | 3개 |
| **CBAM 위치** | 각 Conv 블록 후 | 각 Conv 블록 후 (동일) |
| **출력 구조** | Single-head | **Multi-head (2개)** |
| **출력 활성화** | Sigmoid × 5 | Linear (범위 제한 없음) |

#### 5. 성능 비교

**논문 결과:**
| 모델 | 성능 | 비고 |
|------|------|------|
| 분류 모델 (CBAM 없음) | 94% Accuracy | |
| 분류 모델 (CBAM 포함) | **96% Accuracy** | +2% |
| 회귀 모델 (CBAM 없음) | 78% Accuracy | 반올림 후 정확도 |
| 회귀 모델 (CBAM 포함) | **86% Accuracy** | +8% |

**EGAI 결과:**
| 모델 | MAE | Within-1 Accuracy 추정 |
|------|-----|------------------------|
| Simple CNN | 0.5635 | ~78% |
| CNN + CBAM | 0.4819 | ~82% |
| Multi-head CBAM | **0.4578** | ~85% |

**비교 해석:**
- 논문의 86% vs EGAI의 ~85%는 **비슷한 수준**
- 단, 측정 방식이 다름:
  - 논문: 반올림 후 정확도 (±0이면 정확)
  - EGAI: MAE (연속 오차)

| **모델 구조** | Single-head | Multi-head | 작업별 전문화 |
| **출력 제한** | Sigmoid (0~5) | Linear | - (개선 필요) |
| **Cross Validation** | 없음 | 5-Fold | 안정성 검증 |
| **실험 관리** | 수동 | MLOps 자동화 | 재현성 확보 |

---

### EGAI에서 논문 대비 개선한 부분

#### 1. 4채널 입력 (논문: 2채널)
```
논문:    [Full] + [Percussive]
EGAI:    [Full] + [Percussive] + [Difference] + [Variance]

추가 채널의 의미:
- Difference: 시간에 따른 변화량 → 갑작스러운 이상 감지
- Variance: 불안정한 영역 강조 → 불규칙성 판단에 도움
```

#### 2. Multi-head 출력 (논문: Single-head)
```
논문:    1개 출력 레이어 → 5개 점수 동시 예측

EGAI:    2개 전문화된 헤드
         - Frequency Head: 저고주파, 중주파, 가청범위 (3개)
         - Regularity Head: 규칙성, 불규칙성 (2개)

효과:
- 그래디언트 간섭 방지
- 관련 점수끼리 함께 학습
- irregularity MAE 개선: 0.71 → 0.65
```

#### 3. Cross Validation (논문: 단순 분할)
```
논문:    Train 80% / Test 20% 한 번만 분할
         → 운이 좋은/나쁜 분할에 따라 결과 변동

EGAI:    5-Fold Cross Validation
         → 5번 다른 분할로 평균 성능 측정
         → 결과 신뢰도 높음 (± 표준편차 제공)
```

---

### EGAI에서 논문 대비 부족한 부분

#### 1. 출력 범위 제한 없음 (Critical)
```
논문:    Sigmoid × 5 → 출력이 반드시 0~5 범위
EGAI:    Linear 출력 → 6점, -1점 등 예측 가능

해결 방안 (구현 예정):
x = Dense(num_outputs, activation="sigmoid")(x)
outputs = x * 4 + 1  # 0~1 → 1~5 범위로 변환
```

#### 2. 고장 진단 모델 없음
```
논문:    1단계 - 고장 여부 분류 (96% 정확도)
         2단계 - 정상인 경우만 품질 점수

EGAI:    품질 점수 예측만 수행
         → 고장 데이터 없어 분류 모델 학습 불가

해결 방안 (SERVICE_STRATEGY.md 참조):
- Autoencoder로 이상 탐지 대체
- "안심 범위 / 점검 권장"으로 서비스 설계
```

#### 3. 소음 레벨 지수 (NLI) 미사용
```
논문:    신호처리 기반 NLI 정의
         - Specific Loudness (특정 주파수 대역 비율)
         - SAML (Sum of Audible Modulation Level)

EGAI:    현대차 제공 점수(5개)를 그대로 사용
         → 물리적 의미가 있는 NLI가 아님

향후 고려:
- librosa로 spectral_flatness, spectral_centroid 추출
- 물리량 기반 특징 추가 시 성능 향상 기대
```

### CBAM (어텐션)이란? - 쉽게 설명

**비유: 사진에서 중요한 부분 찾기**

```
일반 CNN:     사진 전체를 똑같이 봄
CBAM 적용:    "이 부분이 중요해!" 하고 집중

엔진 소리에서:
- 특정 주파수 대역에 집중 (채널 어텐션)
- 특정 시간대에 집중 (공간 어텐션)
```

**논문에서 CBAM 효과:**
- 분류 모델: 94% → 96% (+2%)
- 회귀 모델: 78% → 86% (+8%)
- "소음 분석에 어텐션이 특히 효과적" (논문 결론)

## 2.5 한계점과 해결 방안

### 한계점 1: 낮은 점수 예측 불가

**현상:**

- AI가 "2점이 어떤 소리인지" 충분히 학습하지 못함

**해결 가능성:**
| 방법 | 난이도 | 효과 |

| 더 많은 데이터 수집 | 높음 (정비소 협력 필요) | 근본 해결 |
| 데이터 증강 (Augmentation) | 중간 | 부분 개선 |
| 서비스 설계로 우회 | 낮음 | 현실적 |

### 한계점 2: 이상 엔진 데이터 없음

**현상:**
- "고장난 엔진 소리"가 데이터에 없음
- 고장 탐지가 사실상 불가능

**해결 방안:**
→ 서비스 모델 제안에서 상세 설명

### 한계점 3: 출력 범위 제한 없음

**현상:**
```
5점 만점인데 6점으로 예측하는 경우 발생
```

**해결책 (즉시 적용 가능):**
```python
# 모델 출력을 1~5점 범위로 제한
예측값 = max(1, min(5, 예측값))
```

# 3. 서비스 모델 제안

## 3.1 2개 AI 모델 아키텍처

### 왜 2개 모델인가?

논문에서도 **2단계 모델 구조**를 사용했습니다:
1. **1단계 (분류 모델)**: 고장 vs 정상 판단
2. **2단계 (회귀 모델)**: 정상인 경우만 소음 레벨 지수 추정

EGAI도 이와 유사하게 **2개 모델로 서비스**합니다:

```
┌─────────────────────────────────────────────────────────────┐
│                    EGAI 2개 모델 구조                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  [모델 1] Autoencoder (이상 탐지)                    │   │
│  │                                                     │   │
│  │  목적: "정상 범위의 소리인가?" 판단                  │   │
│  │  학습: 정상 데이터(4~5점)만으로 학습                 │   │
│  │  원리: 정상 소리 복원 → 복원 오차로 이상 판단        │   │
│  │                                                     │   │
│  │  장점: 고장 데이터 없이도 이상 탐지 가능             │   │
│  └─────────────────────────────────────────────────────┘   │
│                          ↓                                  │
│                  "안심 범위"인 경우만                        │
│                          ↓                                  │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  [모델 2] Multi-head CBAM CNN (품질 점수)            │   │
│  │                                                     │   │
│  │  목적: 5개 품질 점수 상세 예측                       │   │
│  │  구조: 4채널 입력 → CNN+CBAM → 2개 헤드 출력        │   │
│  │                                                     │   │
│  │  헤드 1 (Frequency): 저고주파, 중주파, 가청범위     │   │
│  │  헤드 2 (Regularity): 규칙성, 불규칙성              │   │
│  │                                                     │   │
│  │  현재 성능: MAE 0.4578 (±0.018)                     │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 논문 vs EGAI 모델 구조 비교

| 단계 | 논문 | EGAI |
|------|------|------|
| **1단계** | 분류 모델 (고장 진단) | **Autoencoder** (이상 탐지) |
| **1단계 학습** | 고장 데이터 필요 | 정상 데이터만 필요 |
| **2단계** | 회귀 모델 (NLI 추정) | **Multi-head CBAM** (5점수) |
| **2단계 구조** | Single-head | **2개 헤드** (Freq + Reg) |

### 왜 Autoencoder인가?

```
문제: 고장난 엔진 데이터가 없음

논문 방식:
  - 고장 부품을 인위적으로 조립해서 고장 소리 수집
  - 정상 vs 고장 분류 모델 학습 (96% 정확도)

EGAI 방식 (Autoencoder):
  - 정상 데이터만으로 "정상이 어떤 소리인지" 학습
  - 새 소리 입력 → 복원 시도 → 복원 오차 측정
  - 오차가 크면 "정상과 다르다" → 점검 권장

장점:
  ✓ 고장 데이터 없이 이상 탐지 가능
  ✓ 본 적 없는 새로운 유형의 이상도 탐지
  ✗ 어떤 부품이 고장인지는 알 수 없음 (한계)
```

## 3.2 핵심 발상의 전환

### 기존 접근 (문제 있음)

```
"엔진 품질 점수를 1~5점으로 예측한다"
→ 1~2점 예측이 안 됨 (데이터 부족)
→ 서비스 신뢰도 하락
```

### 새로운 접근 (제안)

```
"현대 인증 중고차 수준인지 확인한다"
→ 4~5점 범위만 판단 (데이터 충분)
→ 자신 있는 영역에서만 서비스
```

**비유:**
- 기존: "이 차는 몇 점입니다" (전 구간 예측)
- 제안: "이 차는 인증 중고차 수준입니다" (합격/불합격)

## 3.3 2단계 서비스 구조

```
┌─────────────────────────────────────────────┐
│           사용자 엔진 소리 녹음              │
└─────────────────┬───────────────────────────┘
                  ↓
┌─────────────────────────────────────────────┐
│  [1단계] 이상 탐지 (무료)                    │
│                                             │
│  "정상 범위의 소리인가?"                     │
│  → 4~5점 데이터로 학습한 오토인코더 사용     │
│                                             │
│  결과:                                       │
│  ✓ "안심 범위" → 2단계로                    │
│  ⚠ "점검 권장" → 정비소 연결 (무료 종료)    │
└─────────────────┬───────────────────────────┘
                  ↓ (안심 범위인 경우만)
┌─────────────────────────────────────────────┐
│  [2단계] 상세 스코어 (유료)                  │
│                                             │
│  "현대 인증 중고차 기준 어느 수준인가?"       │
│  → Multi-head CBAM 모델 사용                │
│                                             │
│  결과:                                       │
│  "상위 20% 수준입니다"                       │
│  "평균 수준입니다"                           │
│  "하위 30% 수준입니다"                       │
└─────────────────────────────────────────────┘
```

## 3.4 왜 이렇게 설계했나?

### 이유 1: 기술적 한계를 인정

| 우리가 잘하는 것 | 우리가 못하는 것 |
|-----------------|-----------------|
| 4~5점 범위 구분 | 1~2점 예측 |
| "정상 같다" 판단 | "어떤 고장이다" 진단 |

→ **잘하는 것만 유료화, 못하는 것은 "점검 권장"으로**

### 이유 2: 법적 리스크 최소화

| 시나리오 | 리스크 | 우리 대응 |
|---------|--------|----------|
| "정상"이라 했는데 실제 고장 | 매우 높음 | "안심 범위"로 표현 + 면책 |
| "이상"이라 했는데 실제 정상 | 중간 | 무료 제공 + 재측정 유도 |
| "점검 권장" → 고객 불만족 | 낮음 | 정비소 연결로 가치 제공 |

### 이유 3: 수익 모델 명확화

```
무료: 1차 스크리닝 (정상/점검권장)
     → 사용자 획득, 신뢰 구축

유료: 2차 상세 리포트 (9,900원)
     → "안심 범위" 판정받은 사용자만 대상
     → 신뢰도 높은 결과만 제공
```

### 기술적 한계를 비즈니스로 해결

| 문제 | 기술적 한계 | 비즈니스 솔루션 |
|------|------------|----------------|
| 저점수 예측 불가 | 데이터 부족 | "점검 권장"으로 전환 |

> **"당신의 엔진이 현대 인증 중고차 수준인지 확인해드립니다"**

- ✕ 절대적 점수 → ✓ 상대적 위치
- ✕ 이상 진단 → ✓ 안심 인증
- ✕ 기술 과시 → ✓ 사용자 가치

## 부록: 자주 묻는 질문

### Q1: 왜 고장 진단을 안 하나요?

**A:** 고장난 엔진 데이터가 없어서 학습이 불가능합니다.
인증 중고차는 모두 검수를 통과한 "좋은 차"만 있습니다.
향후 정비소 협력을 통해 고장 데이터를 확보하면 가능합니다.

### Q2: 정확도를 더 높일 수 없나요?

**A:** 현재 MAE 0.46 (5점 만점 기준 약 0.5점 오차)입니다.
더 높이려면:
1. 더 다양한 상태의 데이터 필요 (현재 2,234개이나 대부분 고점수)
2. 다양한 상태의 차량 데이터 필요
3. 정비 이력과 연동된 라벨링 필요

### Q3: 실제 서비스까지 얼마나 걸리나요?

**A:**
- MVP (무료 스크리닝만): 3개월
- 유료 서비스 포함: 6개월
- B2B 확장: 12개월

### Q4: 스마트폰 녹음 품질로 충분한가요?

**A:** 현재 MP3 데이터로 학습했으므로 스마트폰 녹음으로 충분합니다.
단, 녹음 환경(주변 소음, 거리 등)에 따라 결과가 달라질 수 있습니다.
앱에서 녹음 가이드를 제공할 예정입니다.
