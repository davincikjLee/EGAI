# 6인 전문가 패널 토론: EGAI 프로젝트 방향성

## 토론 주제
> **"정상 데이터만으로 학습한 모델이 불량을 탐지할 수 있는가?
> 이 프로젝트의 리버스 엔지니어링 가치와 실용화 방향은?"**

## 프로젝트 핵심 정리 (by 사용자)

1. **현재 데이터** = 현대차가 "양호/정상" 판정한 제품
   → Autoencoder로 정상/불량 판별 모델 가능

2. **라벨링 데이터** = 정확하진 않지만 데이터 축적 시 정확도 향상
   → 논문 재현으로 선형적 분류 가능

3. **MP3 수집** = 크롤링으로 지속 확보 가능
   → 학습 데이터로 유효

4. **리버스 엔지니어링** = 라벨링 기준 역추론
   → 새 데이터도 유사 가공하면 사용 가능

5. **진짜 목적** = "내가 사용할 엔진의 상태 확인"

# 🔧 Expert 1: MLOps 전문가

## 핵심 의견

> **"기술적으로 유효하나, 프로덕션 배포 시 데이터 드리프트가 최대 리스크"**

## 상세 분석

### 1. Autoencoder 기반 이상탐지 ✅ 유효

```
기술적 근거:
- One-Class Learning은 정상 데이터만으로 학습 가능
- 594개는 Autoencoder 학습에 충분 (과적합 주의 필요)
- 복원 에러 기반 이상 탐지는 검증된 방법론

권장 구조:
┌─────────────────────────────────────────┐
│  Convolutional Autoencoder              │
│  Encoder: [128x128] → [64x64] → [32x32] │
│  Latent: [8x8x64] = 4096 dim            │
│  Decoder: [32x32] → [64x64] → [128x128] │
│                                         │
│  Loss: MSE + Perceptual Loss            │
│  Threshold: μ + 3σ (정상 복원 에러 기준) │
└─────────────────────────────────────────┘
```

### 2. 리버스 엔지니어링 가치 ✅ 높음

```
MLOps 관점:
- 라벨링 비용 = 0 (현대차가 제공)
- 데이터 품질 = 높음 (전문가 검증된 라벨)
- 확장성 = 높음 (크롤링으로 지속 수집)

단, 주의사항:
- 현대차 라벨링 기준 변경 시 모델 재학습 필요
- 웹사이트 구조 변경 시 크롤러 유지보수 필요
```

### 3. 프로덕션 파이프라인 설계

```
┌──────────────────────────────────────────────────────────┐
│                    Production Pipeline                    │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  [사용자 녹음] → [전처리 서비스] → [추론 서비스]         │
│       ↓               ↓               ↓                 │
│  • 16kHz 리샘플링   • STFT+HPSS    • Model A: 이상탐지  │
│  • 5초 클립         • 정규화        • Model B: 점수예측  │
│  • 노이즈 필터      • 스펙트로그램                       │
│                                                          │
│  [모니터링]                                              │
│  • 입력 분포 감시 (Data Drift Detection)                │
│  • 예측 신뢰도 로깅                                      │
│  • 사용자 피드백 수집                                    │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

### 4. 데이터 드리프트 대응 ⚠️ 중요

```
리스크:
- 녹음 환경 차이 (스마트폰 vs 현대차 장비)
- 새로운 엔진 모델 (학습 데이터에 없는 차종)
- 계절/온도 영향 (여름 vs 겨울 엔진음)

대응 전략:
1. 입력 분포 모니터링 (KL Divergence)
2. Confidence Score 제공 ("예측 신뢰도 70%")
3. Active Learning (저신뢰 샘플 수집 → 재학습)
4. 정기 재학습 (월 1회 크롤링 데이터 추가)
```

### 5. 권장사항

| 우선순위 | 작업 | 이유 |
|----------|------|------|
| **1** | Autoencoder 구현 | 이상탐지 기반 마련 |
| **2** | 추론 API 개발 | 사용자 접근성 |
| **3** | 모니터링 대시보드 | 드리프트 조기 감지 |

# 🎵 Expert 2: 오디오 신호처리 전문가

## 핵심 의견

> **"STFT+HPSS는 엔진음에 적합. MP3 압축 손실은 제한적. 스마트폰 녹음도 가능"**

## 상세 분석

### 1. 현재 전처리 파이프라인 평가 ✅ 적합

```
STFT + HPSS 조합의 장점:
- HPSS가 엔진의 타음(Percussive) 성분 분리 → 노킹 탐지 유리
- Full + Percussive 이중 입력 → 정보 손실 최소화
- 논문(현대차 2023)에서 검증된 방법

개선 가능점:
┌────────────────────────────────────────┐
│ 현재: n_fft=2048, hop=512              │
│ 권장: n_fft=4096, hop=1024             │
│ 이유: 저주파 해상도 향상 (엔진 RPM)    │
│                                        │
│ 현재: 22050Hz                          │
│ 권장: 16000Hz                          │
│ 이유: 8kHz 이상 불필요, 계산 효율      │
└────────────────────────────────────────┘
```

### 2. MP3 압축 손실 영향 ⚠️ 제한적

```
MP3 압축 특성:
- 128kbps 기준 8kHz 이상 손실
- 저주파(엔진 기본 주파수 50~500Hz)는 보존
- 심리음향 모델로 인간에게 안 들리는 성분 제거

엔진음 분석 관점:
- 핵심 주파수 대역 (100Hz~4kHz) 보존됨
- 고장 징후(노킹, 마모음)도 이 대역에 존재
- MP3 사용 유효 ✅

단, 주의:
- WAV로 전환 시 미세한 성능 향상 가능
- 새 녹음은 가능하면 WAV/FLAC 권장
```

### 3. 정상 경계 정의 특징

```python
# 정상 엔진의 오디오 특징 (594개 분석 기반)
normal_features = {
    'spectral_centroid': (800, 1500),      # Hz, 중심 주파수
    'spectral_flatness': (0.1, 0.3),       # 순음 vs 노이즈
    'harmonic_ratio': (0.6, 0.9),          # 하모닉 비율
    'percussive_energy': (0.05, 0.2),      # 타음 에너지 비율
    'zcr': (0.05, 0.15),                   # 영교차율
}

# 경계 밖 = 이상 의심
def detect_anomaly(features):
    for key, (low, high) in normal_features.items():
        if features[key] < low or features[key] > high:
            return True, key
    return False, None
```

### 4. 불량 시뮬레이션 ⚠️ 가능하나 제한적

```
물리적 시뮬레이션 가능한 것:

✅ 베어링 마모: 광대역 노이즈 추가

시뮬레이션 어려운 것:

❌ 미세한 성능 저하

권장:
- 시뮬레이션은 초기 테스트용으로만 사용
```

```
현대차 녹음 조건:
```

# 🤖 Expert 4: 음성/오디오 AI 전문가

## 핵심 의견

> **"Autoencoder 권장. VAE가 더 좋을 수 있음. Transfer Learning은 MIMII 데이터셋 활용"**

## 상세 분석

### 1. 이상탐지 방법론 비교

| 방법 | 장점 | 단점 | 적합도 |
|------|------|------|--------|
| **Autoencoder** | 간단, 검증됨 | 임계값 설정 필요 | ⭐⭐⭐⭐ |
| **VAE** | 확률적 해석, 샘플 생성 | 복잡 | ⭐⭐⭐⭐⭐ |
| **One-Class SVM** | 이론적 보장 | 고차원 어려움 | ⭐⭐⭐ |
| **Isolation Forest** | 빠름 | 특징 엔지니어링 필요 | ⭐⭐⭐ |

```python
# 권장: Convolutional VAE
class ConvVAE:
    def __init__(self):
        self.encoder = build_encoder()  # → μ, log_σ²
        self.decoder = build_decoder()

    def anomaly_score(self, x):
        μ, log_var = self.encoder(x)
        z = reparameterize(μ, log_var)
        x_recon = self.decoder(z)

        # 이상 점수 = 복원 에러 + KL 발산
        recon_loss = mse(x, x_recon)
        kl_loss = kl_divergence(μ, log_var)

        return recon_loss + 0.1 * kl_loss
```

```python
# Contrastive Learning for Engine Audio
class SimCLR_Engine:
    def augment(self, spec):
        # 엔진음에 적합한 증강
        aug1 = time_shift(spec, max_shift=10)
        aug2 = freq_mask(spec, max_width=5)
        return aug1, aug2

    def contrastive_loss(self, z1, z2):
        # 같은 샘플의 증강은 가깝게
        # 다른 샘플은 멀게
        return NT_Xent_loss(z1, z2, temperature=0.5)

# 장점:
# - 라벨 없이 표현 학습
# - 다운스트림 태스크(이상탐지, 점수예측) 모두 활용
```
