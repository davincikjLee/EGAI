## 1. 현재 시스템 구성

### 1.1 3개 모델 체계

EGAI 시스템은 3개의 딥러닝 모델로 구성되어 있습니다:

| 모델 | 목적 | 출력 | 현재 상태 |
|------|------|------|-----------|
| **Regression Model** | 엔진 품질 점수 예측 | 5개 점수 (0~5점) | ✅ 완료 (MAE 0.35) |
| **Binary Model** | 가솔린/디젤 분류 | 확률 (0~1) | ✅ 완료 (F1 0.68) |
| **VAE Model** | 이상 탐지 | 이상 점수 | ✅ 완료 |

### 1.2 입력 데이터

모든 모델은 동일한 **4채널 스펙트로그램** (128×128×4)을 입력으로 사용합니다:

| 채널 | 포착하는 특성 | 설명 |
|------|--------------|------|
| **Full** | 전체 주파수 스펙트럼 | 엔진의 전반적인 음향 특성 |
| **Percussive** | 충격음, 노킹 | 금속성 타격음, 비정상 진동 |
| **Difference** | 급격한 시간 변화 | 순간적인 음향 변화 |
| **Variance** | 불안정한 영역 | 불규칙한 패턴 |

### 1.3 분석 결과 예시

```
==================================================
  [OK] 분석 결과: 양호
==================================================
  종합 점수: 4.24
  저/고주파 균형: 4.15
  중주파 품질: 4.32
  가청범위 상태: 4.89
  규칙성: 4.01
  불규칙성 없음: 3.82
  VAE 점수: 152.3 (낮을수록 정상)
==================================================
```

## 2. 모델 아키텍처 설명

### 2.1 아키텍처 관계도

```
┌─────────────────────────────────────────────────────────────────┐
│                      EGAI 모델 아키텍처                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌─────────────────┐     ┌─────────────────┐                    │
│  │ Regression Model│     │  Binary Model   │                    │
│  ├─────────────────┤     ├─────────────────┤                    │
│  │ CNN + CBAM      │ ←── │ CNN + CBAM      │  ← 동일 백본       │
│  │ (Feature 추출)   │     │ (Feature 추출)   │                    │
│  ├─────────────────┤     ├─────────────────┤                    │
│  │ 5개 출력        │     │ 1개 출력        │  ← 출력만 다름     │
│  │ (품질 점수)      │     │ (가솔린/디젤)    │                    │
│  └─────────────────┘     └─────────────────┘                    │
│                                                                 │
│  ┌─────────────────────────────────────────┐                    │
│  │              VAE Model                  │  ← 완전히 다른 구조│
│  ├─────────────────────────────────────────┤                    │
│  │  Encoder → 잠재공간 → Decoder           │                    │
│  │  (입력 압축)  (128D)   (입력 재구성)      │                    │
│  └─────────────────────────────────────────┘                    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 각 모델의 특징

#### Regression Model (품질 예측)
- **구조**: CNN + CBAM Attention
- **CBAM 역할**: "중요한 영역에 집중"하여 품질 점수 예측
- **출력**: 5개 품질 점수 (저/고주파, 중주파, 가청범위, 규칙성, 불규칙성)

#### Binary Model (연료 분류)
- **구조**: Regression Model과 **동일한 CNN + CBAM 백본**
- **차이점**: 출력층만 다름 (5개 → 1개)
- **장점**: 학습된 특성 추출기 재활용 가능

#### VAE Model (이상 탐지)
- **구조**: Encoder-Decoder (완전히 다른 아키텍처)
- **원리**: 정상 데이터로 학습 → 이상 데이터는 재구성 어려움 → 높은 오차
- **CBAM 미사용 이유**: 아래 참조

### 2.3 VAE에 CBAM을 사용하지 않는 이유

| 관점 | CNN (Regression/Binary) | VAE (이상탐지) |
|------|------------------------|----------------|
| **목표** | 중요 영역에 집중 | 모든 정보 재구성 |
| **CBAM 효과** | 👍 예측 정확도 향상 | 👎 정보 손실 발생 |
| **이유** | 불필요한 영역 무시 OK | 무시하면 이상 탐지 불가 |

```
⚠️ VAE + CBAM 조합이 부적합한 이유:

CNN: "이 부분이 중요하니 여기만 보자" → OK
VAE: "모든 부분을 재구성해야 함" → CBAM이 일부를 무시하면 안 됨

만약 VAE가 어떤 영역을 무시하면:
→ 그 영역에서 이상이 발생해도 탐지 불가
→ 이상탐지 모델로서의 의미 상실
```

## 3. 통합 XAI 시각화

### 3.1 설명가능한 AI (XAI) 란?

AI 모델이 **왜 그런 결정을 내렸는지** 시각적으로 설명하는 기술입니다.

### 3.2 모델별 XAI 기법

| 모델 | XAI 기법 | 시각화 내용 |
|------|----------|------------|
| **Regression** | Grad-CAM | 품질 점수에 영향을 준 영역 (빨간색) |
| **Binary** | Grad-CAM | 연료 유형 구분에 핵심적인 영역 |
| **VAE** | Reconstruction Error | 정상 패턴과 다른 이상 영역 |

### 3.3 통합 시각화 보고서

아래와 같이 3개 모델의 분석 결과를 한 눈에 확인할 수 있습니다:

```
┌────────────────────────────────────────────────────────┐
│            Unified Model Visualization                 │
├────────────────────────────────────────────────────────┤
│                                                        │
│  [Regression]  원본  │  Grad-CAM  │  오버레이         │
│  ──────────────────────────────────────────────────   │
│  [Binary]      원본  │  Grad-CAM  │  오버레이         │
│  ──────────────────────────────────────────────────   │
│  [VAE]         원본  │  재구성    │  오차 맵          │
│                                                        │
└────────────────────────────────────────────────────────┘
```

### 3.4 사용 방법

```bash
# 단일 파일 분석
py -3.12 scripts/visualize_unified.py 엔진소리.m4a

# 폴더 내 모든 파일 분석
py -3.12 scripts/visualize_unified.py sample/
```

**출력물**:
- `파일명.unified_gradcam.png` - 시각화 이미지
- `파일명.unified_gradcam.md` - 분석 보고서

## 4. NG 데이터 요구량 분석

### 4.1 현재 데이터 현황

| 구분 | 수량 | 비율 |
|------|------|------|
| **전체 데이터** | 2,605개 | 100% |
| 가솔린 | 2,407개 | 92.4% |
| 디젤 | 198개 | 7.6% |

**품질 점수 분포**:

| 점수 범위 | 수량 | 비율 | 상태 |
|-----------|------|------|------|
| 4.0점 이상 | 1,968개 | 75.5% | 고품질 (정상) |
| 3.0~4.0점 | 569개 | 21.8% | 중품질 |
| 3.0점 미만 | 3개 | 0.1% | 저품질 |

```
⚠️ 현재 상태: 사실상 정상 데이터만 존재
   → NG(이상) 데이터 수집 필요
```

### 4.2 NG 데이터 요구량

#### VAE 이상탐지용

| 수준 | NG 수량 | 활용 목적 |
|------|---------|----------|
| **최소** | 100개 | 임계값 설정, 기본 검증 |
| **권장** | 200개 | 안정적 분포 학습 |
| **이상적** | 500개 | 다양한 이상 패턴 커버 |

> VAE는 정상 데이터로만 학습하므로, NG 데이터는 **검증용**으로만 필요

#### Binary Classification용 (OK/NG 분류)

| 수준 | NG 수량 | OK:NG 비율 | 기대 F1 |
|------|---------|------------|---------|
| **최소** | 200개 | 10:1 | 0.60~0.70 |
| **권장** | 400개 | 5:1 | 0.75~0.85 |
| **이상적** | 800개 | 2.5:1 | 0.85+ |
